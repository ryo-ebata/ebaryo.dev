# デザイン品質基準

このサイトは、WCAGだけでなく、認知負荷・一貫性・操作感・表示性能を同じ品質ゲートで扱う。

## 1. アクセシビリティ

- WCAG 2.2 AAを自動検査の最低基準とする。
- 通常文字は4.5:1、UI部品と大きな文字は3:1以上を保つ。
- ボタン・入力・選択UIの操作領域は44 × 44 CSS px以上とする。
- キーボード操作、可視フォーカス、意味のあるHTML、適切な名前を必須とする。
- 320 CSS px幅で横スクロールを発生させない。ただし、表やコードなど本質的に二次元のコンテンツは除く。

## 2. 認知負荷と文章理解

W3C COGAの考え方を、次の実装規則へ落とし込む。

- 一画面の主目的を一つにする。
- 初期表示の選択肢は10件を上限とし、それ以上は段階的に開示する。
- ボタン名は操作後の結果を表す。「OK」「実行」だけでは使わない。
- 状態、エラー、次に行う操作を、色だけに依存せず文章でも示す。
- 記事本文は一段落一論点を基本とし、見出しだけでも構造を追えるようにする。

## 3. 可読性

- 公開記事の本文は16px以上、行高1.7以上とする。
- 本文幅は42remを上限とし、日本語でおおむね35〜45字に収める。
- 見出しの途中で一文字だけ次行へ送らない。
- 補助文字でも12px未満を常用しない。装飾ラベルは本文の理解に必須な情報を持たせない。

## 4. デザインシステム

- 色は意味を持つトークンを経由する。コンポーネント内にテーマ依存色を直接書かない。
- `--background`などの全体トークンと、`--writer-*`など領域固有トークンを混用しない。
- 同じ役割の部品は、default・hover・focus・active・disabled・loading・errorの状態を共有する。
- 明示的なサイトテーマをOSテーマより優先する。
- ライト・ダーク・モバイルの画像差分をデザインシステムページで管理する。

## 5. モーションと体感性能

- Core Web Vitalsは75パーセンタイルでLCP 2.5秒以下、INP 200ms以下、CLS 0.1以下を目標とする。
- `prefers-reduced-motion: reduce`では、理解に不要なアニメーションを停止する。
- 操作フィードバックは即時に出し、保存や通信中は状態を文章で通知する。
- レイアウトを変えるアニメーションより、opacityとtransformを優先する。

## 6. 検証コマンド

```bash
pnpm audit:design
pnpm test:e2e -- e2e/accessibility.spec.ts e2e/design-quality.spec.ts --project=chromium
pnpm test:visual
```

静的監査はトークン境界とテーマ同期を、E2Eはコントラスト・操作領域・リフロー・段階的開示を、画像差分は視覚階層と意図しない変化を検出する。

## 7. 記事内容の品質ゲート

執筆画面の「読者理解」はCOGAの考え方を本文へ適用し、次の3段階で扱う。

- 公開ブロッカー: 本文内H1、見出し階層の飛び、altのない画像、名前のないリンク。
- 修正推奨: 300文字を超える段落、抽象的な見出し、曖昧なリンク名、11項目以上の連続リスト。
- 執筆ヒント: 対象と効用が分からない導入、参照先が曖昧な段落冒頭の指示語。

文字数だけで文章を不合格にせず、修正理由と具体的な直し方を示し、該当位置へ移動できることを要件とする。
